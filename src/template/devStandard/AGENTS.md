## 3. 目录结构与职责（新代码必须按此落位）

本节分两层：**3.1 定文件落在磁盘哪里（硬边界，违反即返工），3.2 定代码放在项目里哪一层。**

### 3.1 磁盘落点：公共的进 Public，项目的一律留在项目目录内

工作空间（workspace）是多个项目共用的根目录，结构固定，不要自创：

```
<工作空间>/
├── Public/                     # 公共运行时：多个项目共用，只装一份
│   ├── runtime/                # 数据库 / JDK / Web 服务器等程序本体
│   ├── cache/                  # Maven / npm 等依赖缓存
│   └── downloads/              # 安装包临时区，装完即弃
└── <项目名>/                    # 这个项目的一切，不外溢
    ├── devStandard/            # 项目约束（本文件所在目录）
    ├── doc/                    # 业务流程 JSON
    ├── app/                    # 生成的应用源码（内部结构见 3.2）
    ├── data/                   # 运行期数据：上传文件、附件
    ├── logs/                   # 运行日志
    └── build/                  # 构建产物、发布包
```

四条判定规则，照走不用猜：

1. **能多个项目共用 → Public**。数据库程序、JDK、Web 服务器、依赖缓存，在 Public 里只装一份，不许每个项目重复装。
2. **只服务这个项目 → 项目目录**。源码、建表脚本、配置、上传文件、日志、构建产物，全部在项目目录内。
3. **禁止落在项目目录之外**：临时目录、用户目录、桌面、系统盘根目录，一律不许。
4. **数据库按项目分隔**。共用一个数据库实例，但每个项目用自己的库名 tdev_项目名小写 和自己的账号；禁止跨库读写，禁止删除其他项目的库。

**可迁移要求**：把整个项目目录拷到另一台机器就能跑起来（前提是那台机器 Public 里有对应运行时）。因此：

- 配置文件里**禁止写死绝对路径**（盘符开头的路径、用户目录路径），一律用相对路径或占位符；
- 项目目录名只用 ASCII 字母数字下划线，**禁止中文和空格**——数据库和 Java 对中文路径兼容性差，迁过去就坏。

### 3.2 代码内部结构（分层职责）

```
app/
├── pom.xml
├── sql/                        # 建表/初始化脚本（版本化）
│   └── schema.sql
└── src/main/
    ├── java/com/example/
    │   ├── controller/         # Servlet + AuthFilter：参数解析、权限守卫、写响应，不写业务
    │   ├── service/            # 业务逻辑与事务边界
    │   ├── dao/                # 纯 JDBC 数据访问（唯一允许碰 SQL 的层）
    │   ├── model/              # 数据传输/值对象
    │   ├── redis/              # Redis 客户端封装与 key 管理
    │   ├── ws/                 # WebSocket 端点
    │   └── util/               # 无状态工具类；UserContext / AuthConfig 属框架级例外（请求级上下文，不跨请求、不存业务数据）
    └── webapp/
        ├── index.html          # 静态页面（纯 HTML/JS/CSS）
        ├── js/
        └── css/
```

**代码新增/修改必须落在对应职责目录，禁止跨层越权。**

## 4. 核心约定（必须遵守）

> **本文件只管"在哪放、怎么开工"。** 代码怎么写 = `CODING-STANDARDS.md`；为什么这样分层 = `ARCHITECTURE.md`。同一规则只在一处定义，此处不重复。

1. **新代码照模板**：新增模块必须基于 `scaffold/` 模板生成，不从零画结构。
2. **分层落位**：代码必须落在对应职责目录，禁止跨层越权（分层职责总表见 `ARCHITECTURE.md` 第 2 章）。
3. **不引新依赖**：除 Java 17 / Servlet / MySQL 8 / Redis / 原生 JS 外，不引入任何框架、ORM、前端库或 CDN。
4. **交付前自检**：逐项过 `CODING-STANDARDS.md` 末尾清单；涉及**表结构 / 认证 / 数据归属**的改动，额外过 `ARCHITECTURE.md` 第 11 章清单。

## 5. 三条最致命的反模式

> 完整反模式与自检项见 `CODING-STANDARDS.md` 第 5、6 节，此处只列最容易犯、后果最重的前三条。

- ❌ `SELECT *` / 字符串拼接 SQL
- ❌ Controller 里写 SQL 或业务逻辑
- ❌ 吞异常（`catch (Exception e) {}` 空块）

## 6. 开工流程（每个任务必须按此执行）

1. 读取本文件 + `ARCHITECTURE.md` + `CODING-STANDARDS.md`。
2. 阅读相关现有代码，保持既有风格与命名。
3. 按 `scaffold/` 模板生成新代码。
4. 交付前逐项跑完 `CODING-STANDARDS.md` 末尾的**自检清单**。
