# 多语言（i18n）设计与维护

> 当前支持：**中文（zh，默认）/ English（en）**。切换入口在顶栏右侧下拉框，选择记在 `localStorage.tdev_lang`。

## 1. 为什么用“词典 + DOM 扫描”

TDev 前端是**单文件** `dist/index.html`（~5900 行），界面文案全是内联字符串，逐个改成 `t("key")` 要动几百处、极易漏、还会把代码搞脏。

所以采用：

1. **原文即键**：`"基础信息": "Project Info"`，不引入 key 命名。
2. **首次见到的文本节点记住原文**（`WeakMap`），切语言时按原文翻译 / 还原，**中文模式可以 100% 复原**。
3. **MutationObserver** 监听 `childList / characterData / placeholder·title`，动态渲染（切页、弹窗、流式输出）自动翻译，无需在渲染函数里加调用。
4. `window.alert / confirm` 被包了一层，弹窗文本也走词典。

## 2. 代码位置

全部在 `dist/index.html` 的 `<script>` 开头（“多语言（i18n）”区块）：

| 变量/函数 | 作用 |
| --- | --- |
| `LANG` | 当前语言（`zh` / `en`） |
| `I18N_EN` | **手写核心词典**（菜单、页面标题、部署模块、通用按钮、弹窗） |
| `I18N_EN_EXTRA` | **批量翻译词典**（子 Agent 生成，356 条，覆盖各页面控件） |
| `I18N_RULES` | 带变量的句子（正则 → 英文模板），如「已添加服务器：X」 |
| `tr(s)` | 查表翻译；未命中返回原文 |
| `i18nApply(lang)` | 切语言：写 localStorage、翻译/还原整页 |
| `i18nWatch()` | 起 MutationObserver（全局只起一次） |

## 3. 新增文案怎么加

**不用改调用处**。只要在 `I18N_EN` 里加一条：

```js
"新的按钮文案": "New button label",
```

带变量的句子加到 `I18N_RULES`：

```js
[/^已上传到 (.+)$/, "Uploaded to $1"],
```

## 4. 批量扩充词典的流程（已验证）

1. 用 python 从 `dist/index.html` 抽出所有中文短字符串（长度 ≤24、排除 HTML/提示词长句），写成 `dist/_i18n_keys.txt`；
2. 交给子 Agent 批量翻译成 JSON（键逐字一致、专有名词不译、保留 `{0}` 占位符）；
3. 合并进 `I18N_EN_EXTRA`（不覆盖手写词典）；
4. **删掉 dist 下的临时文件**（dist 会被编进 exe，别把临时文件打进去）；
5. `node --check` 校验脚本 + 抽几个键在 node 里跑 `tr()` 验证，再编译。

## 5. 当前覆盖与已知缺口

- 已覆盖：顶部栏、左侧菜单、各页标题/副标题、基础信息、部署发布、主题风格、项目约束（卡片/表头/按钮）、业务流程（含备份与恢复弹窗）、AI开发（对话区/计划卡状态）、项目空间、模型配置、Agent配置、部署弹窗、通用提示/确认。
- **英文模式下界面已无中文 UI 文案**（自检：切英文 → 采集器写 `app_meta.i18n_missing` → 剩余项只应是语言名、项目名和文档正文）。
- **有意不译**：Agent 提示词正文（发给模型）、用户数据（项目名/流程节点/聊天记录）。
- **待办（卢Sir 指定后续做）**：文档翻译——技术栈表、19 项自检清单、AGENTS.md 正文；计划在 i18n 层新增“文档数据翻译”，不改项目内原文件。
- Agent 回复语言：`agentInstructions()` 在 `LANG === "en"` 时追加 `Reply to the user in English`。
