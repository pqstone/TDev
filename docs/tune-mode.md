# 微调模式（Tune Mode）设计说明

> 状态：已实现（2026-11-13）
> 适用阶段：项目**第一轮开发完成**（流程定义 → 数据结构 → AI 生成代码 → 编译 → 启动，功能结构完整）之后的细节优化阶段。

## 1. 为什么需要

AI 生成的项目结构对了，但细节常常不符合业务习惯：字段顺序、按钮位置、提示文案、校验规则、默认值等。
这个阶段用户的工作方式是**一边看运行中的系统、一边口述调整**，如果每次都切回 TDev 主界面的聊天页，视线会被打断。

所以微调阶段需要一个**极简浮窗**：只有输入框和日志，始终浮在项目页面之上。

## 2. 入口与形态

- 入口：左侧菜单 **「微调模式」**（`data-m="10"`，位于**「工具设置」分组**——项目空间 / 模型配置 / Agent配置 之后，不在「项目工作」组里）。点击**不切换页面**，直接打开浮窗；未选项目或未设工作路径时给出提示。
- **进微调时主窗口自动最小化**（只留浮窗 + 用户要看的目标系统），浮窗起来之后才最小化，开窗失败不会只剩空桌面。
- **回主窗口**：浮窗标题栏有「主窗口」按钮，点击**关闭浮窗并把主窗口从最小化恢复**；右上角 ✕ 走同一条命令（`tune_back_to_main`）—— 主窗口是进微调时收起的，只关浮窗会让程序看起来"没了"。
- 内容只有两块，**分属两个不透明层次**：
  1. **玻璃层**（标题栏 + 执行日志）：跟随标题栏「窗体」滑块整体变透明，**10%–100%（默认 90%）**，记忆到 localStorage `tune_win_alpha`；透明的是窗口本身（窗口 `transparent: true` + 无边框），所以能看到浮窗后面的程序，不是单纯把日志文字调淡。
  2. **输入区**（输入框 + 执行按钮 + 最下方提示）：**始终不透明**（白底 + 边框），透明再低也保证能看清、能点。
- 窗口：独立 Tauri 窗口，label = `tune`，页面 `dist/tune.html`，无系统标题栏（`decorations:false`）+ `transparent:true` + 始终置顶（`always_on_top:true`），默认 560×540，可缩放，居中。
- 标题栏：拖拽区（调用 `tune_drag`）、**窗体**不透明度滑块（10%–100%）、清空日志、「主窗口」、✕。

## 3. 输入规则（卢Sir 明确要求）

| 行为 | 结果 |
|---|---|
| 回车 | **换行**（textarea 默认行为，不监听 Enter） |
| 点击「执行」 | 唯一发送方式，强化"执行"的动作语义，避免输入中途误发 |
| 中文输入法选字回车 | 不会触发执行（根本没有 Enter 处理） |
| 关闭窗口后再打开 | 未发送的草稿恢复（localStorage `tune_draft`） |

## 4. 与「AI开发」共享（2026-11-13 第二轮，卢Sir 要求）

微调不是另一个系统，它是 AI开发 的延续。所以**内容层完全共用**：

| 内容 | 真源（localStorage） | 谁写 | 谁读 |
|---|---|---|---|
| 聊天记录 | `ai_hist_<prjGUID>`（`[{t, me, ts}]`，保留 200 条） | AI开发 `agentHistPush` + 微调窗口 `histPush` | AI开发 `aiRestoreHist()` / 微调启动时载入 |
| 执行输出 | `ai_log_<prjGUID>`（`[{c, m, t}]`，保留 300 条） | AI开发 `aiToolLog` 每行写入 + 微调窗口每条流式事件写入 | AI开发 `aiLogRender()` / 微调启动时载入 |

- **DOM 只是投影**：以前 AI开发 的执行过程只存在 DOM 里，切页面就没了；现在持久化，两个窗口看到同一条流水。
- 微调窗口启动时先铺「与 AI开发 共用的最近对话」和「共用的执行过程（最近 N 条）」，再做本轮。
- AI开发 页在 `renderUi()` 和窗口 `focus` 时重建日志/聊天（执行中不重建，避免打断流式行）。
- 微调窗口的「清」= 清共享日志，AI开发 页的执行过程同步清空。
- 会话名与 AI开发 对齐：`module:ai-code:<prjGUID>`（`sessionMemory: true`，多轮连续）。*注意：AI开发 目前每次 run 仍是独立 session（只发请求头，`/v1/runs` 不认），要真正共享 Agent 上下文需要 AI开发 也带 `session_id`，属后续可选项。*

## 5. 确认项交互（`[[ASK:{...}]]`）

**问题**：Agent 问「要不要改名 / 密码多少」时，微调窗口没有任何交互，Agent 停在那儿，用户只能干等。

**做法**（与 AI开发 的 `aiAskScan` 同一套协议）：

1. 提示词里**强制**要求：需要确认时单独输出一行
   `[[ASK:{"title":"…","body":"…","options":[{"v":"…","label":"…"}],"field":{"key":"…","label":"…","secret":true}}]]`
2. 微调窗口在 delta 累积时扫 `[[ASK:`（`askScan`，同一原文只弹一次），解析成功即弹**阻塞式模态**：
   选项单选 + 输入框（`secret` 用 password 型）+「确定并继续 / 先不做」
3. 答案作为**新一轮 run** 发回同一会话（不是「回答 run 里的挂起请求」——`[[ASK]]` 是文本协议，原 run 已经结束）；密钥类答案写日志时遮蔽成 `[已遮蔽]`
4. 弹窗期间「执行」按钮禁用，状态显示「等你确认」
5. 选「先不做」→ 发回「这一步暂停，请说明状态和下一步建议」，与 AI开发 行为一致

> 若以后要接 Hermes 原生 `approval.request` / `clarify.request`（SSE 控制事件，需要 `POST /v1/runs/{id}/approval|clarify` 才能解除阻塞），得在 Rust 侧 `agent_ask_stream` 里透传事件并新增命令 —— 当前 TDev 三条场景都没用到这条链路。

## 6. 与 Agent 的接口

- 复用现有流式命令 `agent_ask_stream(question, session_id, instructions, cwd)`。
- `session_id = module:ai-code:<prjGUID>`（与 AI开发 对齐）：同一项目内微调**上下文连续**。
- `sessionMemory: true` —— 会话 ID 放进请求体，`/v1/runs` 只认 body 里的 `session_id`（不认 `X-Hermes-Session-Id` 头）。
- `cwd = <工作空间>/<项目名>`：Agent 的工作目录钉死在项目里。
- `window.emit` 是**发往发起 run 的那个窗口**，所以主窗口不会收到微调窗口的流，反之亦然。
- 事件渲染：`reasoning` → 思考行（灰斜体）；`tool` / `tool_done` → 🔧 行；`delta` → 正文行；`done` / `error` 由 invoke 的 Promise 统一收口（避免重复提示）。

## 5. 上下文传递（为什么不走 localStorage）

`tune_open(prjGuid, prjName, cwd)` 把项目上下文写进 Rust 静态变量 `TUNE_CTX`，浮窗启动时用 `tune_ctx` 取。
两个 webview 的 `localStorage` 共享语义不保证，且浮窗可能在项目切换后才打开 —— 走 Rust 侧不依赖时序。

## 6. 微调专用提示词要点

写在 `dist/tune.html` 的 `buildInstructions()`：

1. 先读再改：`doc/data-model.md` 为准；技术栈看 `AGENTS.md` 第 2 章；红线看 `ARCHITECTURE.md` 第 10 章。
2. 最小改动：不重构目录、不换技术栈、不重写已完成模块、不删表字段。
3. 改完自验：编译通过；项目在跑就重启一次让用户看到效果，不反复重启。
4. 收尾说明：改了哪些文件 / 怎么验证 / 需要用户确认什么（3–6 行）。
5. 禁止：删项目目录、改 `src/template/devStandard` 模板、改 `doc` 下流程 JSON、`git push` / 发布线上（用户明确要求除外）。
6. 需求不明确先问一句，不猜着大改；中文、简短、不贴大段代码。

## 7. 权限

- 新增能力文件 `src-tauri/capabilities/tune.json`：只给 `core:default`（事件监听等），**不给** fs / shell / dialog，保持最小化。
- 浮窗关闭、拖拽、开窗都走自定义命令（`tune_close` / `tune_drag` / `tune_open`），不额外开放窗口 API 权限。

## 8. 验收清单

1. 选好项目 → 点左侧「微调模式」→ 浮窗出现，标题显示项目名，日志提示"已就绪 / 工作目录"。
2. 浮窗浮在其他窗口之上；拖动标题栏可移动。
3. 滑块拖动时日志背景透明度实时变化；关窗重开保持上次值。
4. 输入框内回车只换行，不发送；点「执行」才开始跑。
5. 执行中按钮变"执行中…"且不可点，日志出现思考/工具/正文流。
6. 完成后出现"执行完成"，按钮恢复；再执行一次，Agent 记得上一轮（同会话）。
7. 主窗口 AI开发 页的日志不被微调窗口的流污染（双向隔离）。
