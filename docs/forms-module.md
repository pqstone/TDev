# 业务表单模块（Forms）设计说明

> 状态：**已实现**（2026-11-13，`data-m=11`，编译进 exe）
> 定位：把「数据结构设计」从 AI 开发计划里抽出来，做成独立模块，业务视角命名 **业务表单**。
> 菜单位置：`业务流程` → **`业务表单`** → `AI开发`（`data-m="11"`）。

## 1. 为什么抽出来

原来「设计数据结构」是 AI 开发计划的地基第 7 步：必须先生成计划、再点第 7 步执行、出 `doc/data-model.md`，然后才能开始编码。
问题有三：

1. **顺序错了**：表单结构是业务梳理的产物，应该在「业务流程」之后就定下来，而不是混在开发计划里当第 7 步。
2. **看不到、改不了**：产物只有一个 Markdown 文件，用户在界面上看不到字段、数不了字段、改不了字段，发现「客户表少了个手机号」只能重跑整步。
3. **和开发计划耦合**：计划一重新生成，第 7 步的状态就跟着乱。

## 2. 数据契约：`doc/forms.json`（唯一真源）

```json
{
  "version": 1,
  "project": "TestProject",
  "flow": "TestProject_flow.json",
  "generatedAt": "2026-11-13 15:02:11",
  "forms": [
    {
      "key": "customer",
      "table": "t_customer",
      "name": "客户",
      "module": "客户询盘",
      "desc": "客户档案（公司 + 联系人）",
      "fields": [
        {"name": "id", "label": "主键", "type": "bigint", "len": null,
         "required": true, "unique": true, "note": "自增"},
        {"name": "customer_name", "label": "客户名称", "type": "varchar", "len": 64,
         "required": true, "unique": false, "note": ""}
      ],
      "relations": [
        {"type": "1:N", "target": "order", "via": "customer_id", "label": "一个客户多张订单"}
      ]
    }
  ],
  "decisions": [
    {"q": "询盘行与 SKU 是一层还是两层", "choice": "两层", "why": "客户需求与寻源后的实物必须能分别追溯"}
  ]
}
```

- **forms[]**：业务对象（业务人员口中的「表单」）。`name` 是业务名，`table` 是物理表名，`module` 来自业务流程的主阶段。
- **fields[]**：字段级真源，界面直接渲染/编辑它。
- **relations[]**：表单之间关系，`via` 说明外键落在哪张表。
- **decisions[]**：关键设计决策（原 data-model.md 的第 ④ 节），保留叙事，编码时按需查。
- 每张表必须含四尾字段 `id / created_at / created_by / org_id`（由提示词强约束）。

### 派生产物：`doc/data-model.md`

**前端从 forms.json 生成**（`formsToMarkdown()`），不再让模型另写一份，避免两份不一致。结构保持原四节：

1. 业务对象清单（名称 / 表名 / 说明 / 所属模块）
2. 关系说明（1:1 / 1:N / M:N + 外键落点）
3. 每张表的字段（字段名 / 类型 / 约束 / 说明）
4. 关键设计决策（问题 → 选择 → 为什么不选另一个）

这样**原有编码链路零改动**：AI 编码每一步的提示词第 0 条本来就是「先读 doc/data-model.md」，读完就拿到最新结构。

## 3. 界面（左侧 Agent 对话 + 右侧操作面板，与 AI开发 同款排版）

### 左：Agent 对话
- 场景 `forms`（`AGENT_SCENES.forms`），会话前缀 `module:forms`，聊天记录 key `forms_hist_<prjGUID>`（**不能**落进 `ai_hist_`，否则和 AI开发 串台）。
- 输入框支持多行（复用 `bindComposer`），Enter 发送、Shift+Enter 换行。
- 用途：生成/追加/修改表单，例如「再给我加一张询盘跟进记录，字段要跟进人、跟进时间、结果」。

### 右：操作面板
- **顶部统计条**：`N 个表单 · M 个字段 · K 条关系`（需求 5：体现字段数量）
- **工具按钮**：`生成业务表单`（无流程时禁用并说明原因）、`保存`
- **表单卡片**（可折叠）：
  - 头部：业务名 + 表名 + `字段 N` + `关系 K` 徽标 + 所属模块标签 + 删除
  - 展开后是**字段表格**，每格都是 `input`/`select`，直接改：
    `字段名 | 中文名 | 类型 | 必填 | 唯一 | 说明 | 删除`，底部 `+ 添加字段`
  - **关系区**：`1:N → 订单 · via customer_id · 说明`，可编辑、可删、可加
- **三态齐全**：
  - 无项目 → 提示先选项目
  - 有项目但**没有业务流程** → 提示「先去『业务流程』梳理」（需求 4：生成前提）
  - 有流程无表单 → 引导点「生成业务表单」

## 4. 交互与持久化

| 动作 | 行为 |
|---|---|
| 生成 | 读流程 JSON 全文 → `agentRun("forms", prompt)` → 解析 `[[FORMS]]…[[/FORMS]]` → 渲染 → 自动保存 |
| 编辑 | 改字段/关系后 `dirty=true`，底部提示「有未保存的修改」；点「保存」写入 |
| 保存 | `process_save` 写 `doc/forms.json` + `doc/data-model.md`（自动进 `doc/versions/` 备份，沿用现有逻辑） |
| 切换项目 | `PRJ_REFRESH[11] = renderForms`，按项目重新载入 |
| 清空/重来 | 卡片删除 / 对话里说「删掉 xx 表单」，重生成时整体替换 |

## 5. 与 AI 开发计划的衔接

0. **菜单绿灯**：表单保存成功（或载入到已有 forms.json）即 `modSet("forms", true)`，`module_state_get` 对老项目会探测 `doc/forms.json` 是否存在来补亮。
1. `aiBuildBaseSteps()`：**删掉第 7 步「设计数据结构」**，地基回到 6 步（准备数据库 / 准备运行环境 / 检查地基 / 搭项目骨架 / 注册登录 / 权限校验）。
2. 第 7 步的专属方法论提示词（业务对象、五类关系、快照 vs 引用、四节文档）**整体搬到 `formsPrompt()`**，一词不丢。
3. AI 编码单步提示词第 0 条改为：
   > 开工前先读 `doc/data-model.md`（由「业务表单」模块生成；不存在就说明「还没生成业务表单，请先去该模块生成」并跳过这一步的表结构改动）
   表 / 字段 / 接口改动一律照它来。
4. 开发计划面板上的「📐 数据结构文档」按钮改为「📐 业务表单」，点击跳到本模块（`render(11)`），不再在第 9 页里编辑。

> 老计划（已含 7 步地基）不受影响：步骤列表存在 localStorage，按位置保留进度；重新生成后会变成 6 步地基。

## 5.1 AI 开发前置闸门（`aiGateCheck`）

AI 开发**所有会真正跑 Agent 的入口**（生成开发计划 / 一起开始 / 单步执行）先过闸门：

```
基础信息 → 主题风格 → 项目约束 → 业务流程 → 业务表单
```

- 全部亮绿灯才放行；缺哪个就弹「前序模块未完成」模态，按钮「去「X」」直接 `render()` 到那个模块。
- 数据源统一 `module_state_get`（SQLite `module_state`），前端不再各自判断。
- 读取失败时 **fail-open 不拦人**（别把用户锁死在读不到状态的场景里）。
- 实现：`aiGenPlan(retry, gated)` / `aiPlanStart(gated)` / `aiPlanRunStep(n, gated)` 都加了 `gated === true` 的二次进入保护，避免异步回调里重复过闸或死循环。

## 6. 验收清单

1. 无流程时，右面板显示「先去业务流程」且「生成业务表单」不可点。
2. 有流程 → 点生成 → 出现表单卡片，统计条字段数正确。
3. 展开卡片 → 改一个字段名 / 勾掉必填 / 加一个字段 → 点保存 → 关掉页面再进来，改动还在。
4. `doc/forms.json` 与 `doc/data-model.md` 都生成，md 里的字段数与界面一致。
5. 删除一张表单 → 保存 → 统计条数字跟着变。
6. 回到 AI开发：地基变 6 步；第 7 步不再是「设计数据结构」。
7. 在 AI开发 里执行任一步，Agent 读到的是最新 `doc/data-model.md`。
